### **1. Original Code**

Here, the `isEven` function executes directly **during render** every time the component re-renders, even when it's not necessary.

```jsx
import React, { useState } from "react";

function Counter() {
  const [counterOne, setCounterOne] = useState(0);
  const [counterTwo, setCounterTwo] = useState(0);

  // Increment counterOne
  const incrementOne = () => {
    setCounterOne(counterOne + 1);
  };

  // Increment counterTwo
  const incrementTwo = () => {
    setCounterTwo(counterTwo + 1);
  };

  // Expensive function runs on every render
  const isEven = () => {
    let i = 0;
    while (i < 200000000) i++;
    return counterOne % 2 === 0;
  };

  return (
    <div>
      <div>
        <button onClick={incrementOne}>Count One - {counterOne}</button>
        <span>{isEven() ? " Even" : " Odd"}</span>
      </div>
      <div>
        <button onClick={incrementTwo}>Count Two - {counterTwo}</button>
      </div>
    </div>
  );
}

export default Counter;
```

#### **Problems**:
- Every time the component re-renders, the `isEven` function runs, regardless of which state changed.
- Clicking the **"Count Two" button** unnecessarily executes `isEven`.

### **2. useMemo Version**

In this version, we use `useMemo` to memoize the result of `isEven` so that it only recalculates when `counterOne` changes.

```jsx
import React, { useState, useMemo } from "react";

function Counter() {
  const [counterOne, setCounterOne] = useState(0);
  const [counterTwo, setCounterTwo] = useState(0);

  // Increment counterOne
  const incrementOne = () => {
    setCounterOne(counterOne + 1);
  };

  // Increment counterTwo
  const incrementTwo = () => {
    setCounterTwo(counterTwo + 1);
  };

  // Memoize the result of the expensive function
  const isEven = useMemo(() => {
    let i = 0;
    while (i < 200000000) i++;
    return counterOne % 2 === 0;
  }, [counterOne]);

  return (
    <div>
      <div>
        <button onClick={incrementOne}>Count One - {counterOne}</button>
        <span>{isEven ? " Even" : " Odd"}</span>
      </div>
      <div>
        <button onClick={incrementTwo}>Count Two - {counterTwo}</button>
      </div>
    </div>
  );
}

export default Counter;
```

#### **Benefits**:
- `isEven` only recalculates when `counterOne` changes.
- Clicking **"Count Two" button** does not trigger the expensive computation.

### **3. Modified Version** (Your Approach)

In this version, you calculate the result of `isEven` only **inside the `incrementOne` function** and store the result in state (`a`). This completely decouples the expensive function from rendering.

```jsx
import React, { useState } from "react";

function Counter() {
  const [counterOne, setCounterOne] = useState(0);
  const [counterTwo, setCounterTwo] = useState(0);
  const [a, seta] = useState(0);

  // Increment counterOne and call isEven
  const incrementOne = () => {
    setCounterOne(counterOne + 1);
    isEven();
  };

  // Increment counterTwo
  const incrementTwo = () => {
    setCounterTwo(counterTwo + 1);
  };

  // Expensive function - called explicitly
  const isEven = () => {
    let i = 0;
    while (i < 200000000) i++;
    seta(counterOne % 2 === 0);
  };

  return (
    <div>
      <div>
        <button onClick={incrementOne}>Count One - {counterOne}</button>
        <span>{a ? " Even" : " Odd"}</span>
      </div>
      <div>
        <button onClick={incrementTwo}>Count Two - {counterTwo}</button>
      </div>
    </div>
  );
}

export default Counter;
```

#### **Benefits**:
- `isEven` is only called **when "Count One" button** is clicked.
- The result of `isEven` is stored in state (`a`) and reused during re-renders.
- Clicking **"Count Two" button** does not trigger `isEven` or the expensive computation.

#### **Drawbacks**:
- The `isEven` function must be explicitly called.
- The result is stored in state, which introduces a slight increase in memory usage.

- **If `isEven` needs to be updated only when `counterOne` changes:** Use the **`useMemo` version**.
- **If you want full control and avoid unnecessary calls during render:** Use your **Modified Version**.

Both approaches solve the unnecessary execution issue, and you can choose based on your preferences or project requirements.

### **Why does the Original Code lead to a problem?**

In the original code, the `isEven` function runs **every time the component re-renders**, even when it doesn't need to.

- Clicking **"Count Two" button** causes a state update (`counterTwo`).
- React re-renders the entire component, and during that render, the `isEven()` function executes again.
- This happens because `isEven()` is called directly inside the JSX and has no condition to prevent unnecessary execution.

Since `isEven` contains a **slow/expensive computation** (the `while` loop), this causes performance issues.

---

### **What is `useMemo`?**

`useMemo` **memoizes** (remembers) the result of an expensive function. It **only recalculates** the result when its dependencies change.

#### **Syntax**:
```jsx
const result = useMemo(() => {
  // Expensive computation
  return something;
}, [dependency]);
```

#### **How `useMemo` helps here**:
In the improved code:
```jsx
const isEven = useMemo(() => {
  let i = 0;
  while (i < 200000000) i++;
  return counterOne % 2 === 0;
}, [counterOne]);
```
- The `isEven` function is **only re-executed when `counterOne` changes**.
- If you click **"Count Two" button**, `counterOne` does not change, so the result is reused without re-running the function.

---

### **Summary**:
- **Original Code**: `isEven` runs on every render → unnecessary work.
- **`useMemo`**: `isEven` runs **only when `counterOne` changes** → better performance.
